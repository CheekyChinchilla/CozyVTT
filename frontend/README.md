# CozyVTT Frontend

React 19 + TypeScript + Vite SPA. Talks to the [backend](../backend/) over REST and Socket.io. Needs Node.js 26, the version `.nvmrc` names.

## Quick commands

```bash
npm install              # install deps
npm run dev              # vite dev server on :3000 (proxies /api and /socket.io to :4000)
npm run build            # production build → dist/
npm run preview          # serve the built dist/ locally
npm run test:run         # vitest one-shot (npm test is watch mode)
npm run test:coverage    # vitest one-shot with a coverage report
npm run test:e2e         # Playwright smoke tests against a running instance (e2e/)
npm run lint             # eslint, flat config in eslint.config.js; fails on any warning
npm run typecheck        # type-check the app, e2e/, vite.config.ts and vitest.config.ts
```

## Where things live

- [`src/components/`](src/components/) — reusable UI
- [`src/pages/`](src/pages/) — top-level route components
- [`src/contexts/`](src/contexts/) — global React state (Auth, Campaign, WebSocket, Theme, Toast)
- [`src/services/api.ts`](src/services/api.ts) — REST client (Axios)
- [`src/services/socket.ts`](src/services/socket.ts) — Socket.io client. Subscribe through its `on…` methods and unsubscribe with `off(event, handler)`: it rebuilds the socket on reconnect and re-attaches only what it holds, so a listener bound to `getSocket()` dies with the first socket
- [`src/services/api.ts`](src/services/api.ts) sends a page to sign in on a 401 (`services/pageLoad.ts`, carrying the page as `?next=`, checked by `utils/returnTo.ts`), except on a public page or while an editor holds unsaved changes (`services/unsavedWork.ts`). A 401 with `code: 'SIGN_IN_EXPIRED'` leaves its sentence for the sign-in page (`services/signInNotice.ts`). A 403 with `PASSWORD_CHANGE_REQUIRED` or `MFA_ENROLMENT_REQUIRED` sends the page to change the password or set up MFA. A call whose 401 means a wrong password or code, not a lost sign-in, passes `skipAuthRedirect` so its form can show the message
- [`src/constants/`](src/constants/) — game system labels, and limits copied byte for byte from the backend (`mapLimits.ts`, `sheetLimits.ts`, `assetLimits.ts`, `inviteSearchLimits.ts`, `statBlockLimits.ts`, `tokenLimits.ts`, `campaignLimits.ts`, `chatLimits.ts`, `drawingLimits.ts`, and `uploadTypes.ts`, the files each kind of asset may be). So are several files in `src/utils/` (`raycasting.ts`, `spatialIndex.ts`, `visibilityRule.ts`, `tokenMask.ts`, `tokenCentre.ts`, `vibeAudio.ts`, `drawingRules.ts`, `characterHp.ts`, `styleAllowlists.ts`) and `src/utils/rules/`. Change both copies together: backend tests fail while they differ. `layout.ts` holds `COMPACT_LAYOUT_QUERY`, the width below which the campaign page, the Creature Library and Token Templates change for a narrow screen: the exact complement of Tailwind's `lg`, in rem as `lg` is, so the two agree at any default text size. Ask it through `useMediaQuery(COMPACT_LAYOUT_QUERY)` and never write the width again, which `constants/__tests__/layout.test.ts` refuses
- [`src/utils/clipboard.ts`](src/utils/clipboard.ts) — `copyText`, which works on plain HTTP and says whether it copied. Use it, not `navigator.clipboard`, which is undefined outside HTTPS
- [`src/utils/errors.ts`](src/utils/errors.ts) — `errorSummary` for console lines. Never log a caught API error whole: it carries the request body, a password or a code among them, and error lines are kept in production builds. `src/__tests__/errorLogging.test.ts` fails when a console line passes a caught error whole, except the few it names that are not API errors
- [`src/utils/rollModes.ts`](src/utils/rollModes.ts) — rolling a d20 test in a mode. `applyRollMode` turns a leading `1d20` into `2d20kh1` or `2d20kl1` and names the mode in the purpose, which is how the dice log says so; Normal, a system with no such rule (Call of Cthulhu) and a roll that does not begin with one d20 come back unchanged. Every place that rolls with advantage or disadvantage rolls through it: the roll pickers' **Roll mode**, a sheet's **Roll mode** and the sheet's roll menu. `getModeLabels` names the modes per system (Fortune and Misfortune in Pathfinder 2e). The caller decides what is a test: a damage roll or a hit die is never passed to it
- [`src/types/index.ts`](src/types/index.ts) — TypeScript types mirroring the backend. Two are checked against it: the sheet types in `src/types/game-systems/` against the backend's Zod schemas, and `GameSystem` (`src/types/gameSystem.ts`) against `schema.prisma`. `backend/src/__tests__/keepInStep.test.ts` fails when either drifts, and names the frontend line
- [`src/types/drawings.ts`](src/types/drawings.ts) — a drawing on the map as the server sends it (`Drawing`, with the fields of the server's `DrawingSent`, of the same types) each drawing event the draw tool sends (named as the server's schema for it names them), and each the server sends (named as the server's interfaces for them, in `backend/src/services/mapDrawings.ts`, name them, the same fields optional); `keepInStep.test.ts` fails while any differs
- [`src/index.css`](src/index.css) — the theme tokens and the shared utilities. `touch-target` makes a control at least 44 by 44 CSS px where the primary pointer is coarse (a phone or a tablet) and leaves its size alone for a mouse: give it to any control a finger must hit that is not a `<Button iconOnly>` or `<Button size="sm">`, which carry it already. It sets no display, so a lone icon is centred by the control's own classes (`inline-flex items-center justify-center`); a menu item takes `pointer-coarse:min-h-11` instead, and a menu `pointer-coarse:max-h-[calc(100dvh-1rem)]` with `pointer-coarse:overflow-y-auto`. jsdom evaluates no media query, so a test asserts the class. Where the pointer is coarse, every text box, dropdown and text area is drawn at 16 px or more, since Safari on iOS zooms the page when a smaller one takes focus: `text-xs` and `text-sm` read 16 px on a control there, a control with no size class takes its parent's size but not less, and the sizes in pixels below 16 that components write are named in a rule of their own, which `styles/__tests__/touchFormControls.test.ts` keeps complete; it also refuses a text size it cannot read (em, a percentage, `clamp()`, a variable), a font size in a style object (unless its expression starts `Math.max(coarsePointer ? 16 :`, for a size that must follow something a class cannot, such as the drawing label box following the map's zoom) and a font size in a stylesheet it does not know. The `short:` variant is a screen under 500 px tall, such as a phone turned sideways, and sorts after the breakpoints, so `sm:p-4 short:p-0` is `p-0` there; code that must follow it asks `useMediaQuery(SHORT_SCREEN_QUERY)` (`src/constants/layout.ts`)
- [`src/themes.ts`](src/themes.ts) — built-in color themes and font families
- [`src/assets/fonts/`](src/assets/fonts/) — the typefaces those font families name, served by the instance itself, with one `@font-face` per family and character range (and per weight, for a family with no variable font) in `fonts.css` and the licences in `OFL.txt`. A new font family needs its files and rules here; `src/__tests__/fonts.test.ts` fails until each family a font choice names first has them
- [`src/components/character-sheets/`](src/components/character-sheets/) — per-game-system character sheet implementations. `SheetTabs.tsx` is the tab bar every tabbed sheet and editor draws: buttons, the open one marked with `aria-current` and underlined in the header colour, wrapping onto more rows where they do not fit. `flexible/components/DragEntry.tsx` is a section or list entry of the flexible editor that can be dragged: by its grip with a finger or a pen, from anywhere but a text box with a mouse. `__tests__/smallScreenClasses.test.ts` refuses a grid of four or more columns on a phone, unless it is listed there with its reason, and a height from the screen below `sm`, in any sheet. `SheetRollPopup.tsx` is the roll menu of a sheet that rolls with advantage (D&D 5e, Pathfinder 2e): Normal, Advantage and Disadvantage for one d20 test, by `applyRollMode`, opened at the point and kept inside the screen (`placeRollPopup`), closed by a pointerdown anywhere else (a mousedown alone is what iOS sends as a long-press lifts) or by Escape, which leaves the sheet open since the menu has a focus trap of its own. `useSheetRolls.tsx` holds a sheet's open menu and its roll handlers, so the sheets keep no roll state of their own: `rollTest` rolls a d20 test in the sheet's Roll mode, `roll` a damage roll or a hit die as written, and `rootProps`, spread on the sheet's root, open the menu for a right-click or a finger's press and hold on any row that carries `rollTarget(expression, purpose, gameSystem)`'s attributes, through `useLongPress` with `within`. A row that rolls a test spreads those attributes, which give it its title too, and adds `select-none [-webkit-touch-callout:none]`. `RollModeControl.tsx` is that **Roll mode** (Normal, Advantage, Disadvantage, as `getModeLabels` names them), which `components/character/CharacterSheetViewerModal.tsx` holds per open sheet, starting at Normal and never stored, and shows wherever the sheet rolls and `systemSupportsAdvantage` says the system has the rule
- [`src/components/character/sheetShell.ts`](src/components/character/sheetShell.ts) — the frame the character sheet viewer and its editor share: the whole screen below `sm` and on a `short:` screen, the window it always was from `sm` up. Both dialogs are portaled to the body, as `Modal` is, since they are opened inside the roster, the initiative tracker and the map
- [`src/components/campaign/map/mapPointer.ts`](src/components/campaign/map/mapPointer.ts) — `MapPointer`, the one shape a map tool reads a pointer in, made from a pointer event (or the context menu's mouse event), with the click count MapCanvas keeps, since a pointer event's own `detail` is 0
- [`src/components/campaign/map/gestures.ts`](src/components/campaign/map/gestures.ts) — the touch gesture recogniser: taps, long-presses, drags and pinches from pointer samples, with no DOM, so each rule is tested alone with fake timers. Mouse and pen samples make no gesture. `longPressAt` lets the map refuse a long-press as a press lands (under a DM tool), and `hold(id)` holds a press when the browser made its own long-press (Android's `contextmenu`), which `isHeld(id)` then reports. `LONG_PRESS_MS` and `TAP_SLOP_PX` are its two numbers, half a second and 8 pixels; read them from here

With `within`, one handler serves many rows: only a press landing inside an element matching the selector is timed, and `onOpen` is given that element. Coordinates everywhere else stay in CSS pixels, and each layer sets its world transform with `applyViewport` only
- [`src/components/campaign/map/layers/drawDrawings.ts`](src/components/campaign/map/layers/drawDrawings.ts) — the drawings on a map, and the previews of strokes on their way and of the laser pointer. Pure, like every layer: the traced outline of each drawing is kept in a `DrawingCache` the caller holds, keyed by the drawing object, so a pan strokes the same `Path2D`s again and a changed drawing (a new object) is traced again; a drawing wholly outside the part of the map on screen is skipped. jsdom has no `Path2D`, so there the outline is traced into the context each time. The markup layer's pixels are kept in the cache too (`drawMarkupLayer`), drawn again only when the drawings, the view, the canvas's size or the labels' measures change and copied onto the overlay at every other repaint; a label is measured once, and again after a font loads (`watchLabelFonts`); a laser's trail is stroked in eight strengths a pass, one path each, however many points it holds. A drawing for the DM alone is drawn dashed and faded when `showDmOnly` (the DM's own view) and left out otherwise. [`map/drawingGeometry.ts`](src/components/campaign/map/drawingGeometry.ts) holds the shapes the layer and the eraser's hit test share: the drawing order, a drawing's box, an arrow's head, a label's size
- [`src/components/campaign/map/drawingHitTest.ts`](src/components/campaign/map/drawingHitTest.ts) — which drawing a press lands on, for the eraser: the topmost whose stroke is within half its width and `hitTolerance` of the point (6 screen pixels for a mouse or a pen, 16 for a finger, divided by the zoom), or, filled, holds it; a label by the box its words take. The caller passes only what its screen draws and its viewer may erase
- [`src/components/campaign/map/useMapDrawings.ts`](src/components/campaign/map/useMapDrawings.ts) — the drawings on the map on screen, kept in the game store (`drawings`): asked for on each join, map and role, changed by the server's drawing events (those for another map ignored), and the page's own adds, erases and clears shown at once and put right when refused. Its own add is drawn as `pending:<opId>` until the echo or the answer names the stored drawing. Listen through the socket client's `on…` methods, as here, so a rebuilt socket keeps the listeners
- [`src/components/campaign/map/drawingPreviews.ts`](src/components/campaign/map/drawingPreviews.ts) — the strokes on their way a page shows, built from their senders' frames with no DOM: a pen stroke's, a polygon's and the laser's points appended, a line's, an arrow's, a rectangle's and an ellipse's two points replaced, an `end` frame dropping it, and one whose sender goes quiet dropped 3 seconds after its last frame (a laser's points as they age). The server bounds frames a second, not strokes, so a page keeps at most `PREVIEWS_KEPT_PER_SENDER` (4) strokes from one sender and `PREVIEW_POINTS_KEPT` (20,000) points in all, the stalest going first; and which drawings a `drawings:cleared` took
- [`src/components/campaign/map/tools/useDrawTool.ts`](src/components/campaign/map/tools/useDrawTool.ts) — the draw tool, a `MapTool` asked after the armed Ping and before the DM's tools: the pen, the shapes, the polygon (closed by a tap on its first corner or **Done**), the text label's box, the eraser (by `drawingAt`, among what `canEraseDrawing` allows) and the laser pointer. Its press lasts from its own down to its up, so a hovering pen draws nothing; its preview frames go at most `previewFramesPerSecond` a second, and one a second while held still or between a polygon's corners; whatever cancels a stroke (a second finger, `pointercancel`, blur, Esc, a map switch, unmounting) sends an end frame, except the laser pointer's, whose trail is left to fade. A player who may not draw now, with drawings of their own on the map, is offered the eraser and **Clear mine** alone (`onlyErase`). The DM's panel lists each other member with drawings on the map, to clear alone (`clearMember`). [`DrawControls.tsx`](src/components/campaign/DrawControls.tsx) is its panel, with no place of its own, so the DM's tool stack or a player's corner can hold it. On the compact layout [`DrawStrip.tsx`](src/components/campaign/DrawStrip.tsx) holds the same controls as a strip across the map's foot (on a tablet at most the sheets' 672 pixels, centred), last in the map's dock (the details card left out while it is up), with the map live above it and no focus trap: a header with **Draw**, **Clear…** for the DM (an action sheet of every drawing or one member's, each asked first through the panel's own `ClearDrawingsDialogs`) or **Clear mine**, and **Done**, which gives the focus to the band's **Draw**; the tool's hint; the nine tools in one row that scrolls sideways; a colour button opening the eight colours and **Another colour**, and **Width**; **Fill shapes**, **Snap to grid** and **Only I can see this** as chips; every control 44 pixels. While a polygon is open its **Cancel** and **Done** take the header's place, so one **Done** shows at a time. The strip is at most half the map's height (`max-h-[50cqh]`, 45 on a `short:` screen, the dock being a size container the map's size), its header fixed and the rest scrolling under it; on a short screen (`SHORT_SCREEN_QUERY`) the tools move into the header's row. The two share the tools, colours, hints and questions, exported by `DrawControls.tsx`
- [`src/components/common/Markdown.tsx`](src/components/common/Markdown.tsx) — the one Markdown renderer (notes, documents). Import it; do not use `react-markdown` directly, so raw HTML stays off and the plugin set stays the same everywhere
- [`src/test/`](src/test/) — the Vitest setup file, which adds the jest-dom matchers to `expect` through `@testing-library/jest-dom/vitest` and stubs the pointer capture jsdom lacks; `pointer.ts`, which fires pointer events as a browser does (no `detail`, a move's `button` -1, a second button as a move); `waitForDialogFocus`, which a test calls before typing into a dialog that has just opened: the dialog moves focus to its first control on the next animation frame, and keys typed after that move are lost. It waits for a frame of its own, since a field with `autoFocus` puts focus inside the dialog before that move; `recordingCanvas.ts`, for a test that looks at what the map's layers draw through MapCanvas: every canvas gets a context that records its calls, and the pictures jsdom never loads wait to be loaded by hand; and `characterMenuRows.ts`, the roster's and the initiative tracker's character menu open now, a row a line with its icon and how it looks, failing on any classes or markup the menu does not have today
- [`e2e/`](e2e/) — a handful of Playwright smoke tests: a real browser against a running instance, in Chromium at desktop and phone sizes and in WebKit on an iPhone and an iPad. CI runs them against the production stack; `e2e/instance.ts` says which settings they read, and `docs/DEVELOPMENT.md` how to run them locally. Vitest leaves the folder alone. Keep them few: behaviour belongs in Vitest tests
- [`vite.config.ts`](vite.config.ts) — the production build (Vite 8) removes every `console.log`, `console.info`, `console.debug` and `console.trace` call (`build.rolldownOptions.treeshake.manualPureFunctions`), and the minifier drops `debugger`; `console.error` and `console.warn` stay. The dev server keeps every log, and CI fails if one of four known `console.log` lines turns up in the bundle. It also names the five `vendor-*` chunks, and builds for Chrome and Edge 111, Firefox 114 and Safari 16.4, Vite's default
- [`security-headers.conf`](security-headers.conf) — the Content-Security-Policy and other headers the production image serves the app page with. Included by [`nginx.conf`](nginx.conf) in every location, because nginx does not inherit them. Anything loading from a new host has to be allowed here, and the dev server has no policy, so a violation only shows up in a production build
