# CozyVTT Frontend

React 19 + TypeScript + Vite SPA. Talks to the [backend](../backend/) over REST and Socket.io. Needs Node.js 26, the version `.nvmrc` names.

## Quick commands

```bash
npm install              # install deps
npm run dev              # vite dev server on :3000 (proxies /api and /socket.io to :4000)
npm run build            # production build → dist/
npm run preview          # serve the built dist/ locally
npm run test:run         # vitest one-shot (npm test is watch mode)
npm run test:coverage    # vitest one-shot with a coverage report
npm run test:e2e         # Playwright smoke tests against a running instance (e2e/)
npm run lint             # eslint, flat config in eslint.config.js; fails on any warning
npm run typecheck        # type-check the app, e2e/, vite.config.ts and vitest.config.ts
```

## Where things live

- [`src/components/`](src/components/) — reusable UI
- [`src/pages/`](src/pages/) — top-level route components
- [`src/contexts/`](src/contexts/) — global React state (Auth, Campaign, WebSocket, Theme, Toast)
- [`src/services/api.ts`](src/services/api.ts) — REST client (Axios)
- [`src/services/socket.ts`](src/services/socket.ts) — Socket.io client. Subscribe through its `on…` methods and unsubscribe with `off(event, handler)`: it rebuilds the socket on reconnect and re-attaches only what it holds, so a listener bound to `getSocket()` dies with the first socket
- [`src/services/api.ts`](src/services/api.ts) sends a page to sign in on a 401 (`services/pageLoad.ts`, carrying the page as `?next=`, checked by `utils/returnTo.ts`), except on a public page or while an editor holds unsaved changes (`services/unsavedWork.ts`). A 401 with `code: 'SIGN_IN_EXPIRED'` leaves its sentence for the sign-in page (`services/signInNotice.ts`). A 403 with `PASSWORD_CHANGE_REQUIRED` or `MFA_ENROLMENT_REQUIRED` sends the page to change the password or set up MFA. A call whose 401 means a wrong password or code, not a lost sign-in, passes `skipAuthRedirect` so its form can show the message
- [`src/constants/`](src/constants/) — game system labels, and limits copied byte for byte from the backend (`mapLimits.ts`, `sheetLimits.ts`, `assetLimits.ts`, `inviteSearchLimits.ts`, `statBlockLimits.ts`, `tokenLimits.ts`, `campaignLimits.ts`, `chatLimits.ts`, and `uploadTypes.ts`, the files each kind of asset may be). So are several files in `src/utils/` (`raycasting.ts`, `spatialIndex.ts`, `visibilityRule.ts`, `tokenMask.ts`, `tokenCentre.ts`, `vibeAudio.ts`, `characterHp.ts`, `styleAllowlists.ts`) and `src/utils/rules/`. Change both copies together: backend tests fail while they differ
- [`src/utils/clipboard.ts`](src/utils/clipboard.ts) — `copyText`, which works on plain HTTP and says whether it copied. Use it, not `navigator.clipboard`, which is undefined outside HTTPS
- [`src/utils/errors.ts`](src/utils/errors.ts) — `errorSummary` for console lines. Never log a caught API error whole: it carries the request body, a password or a code among them, and error lines are kept in production builds. `src/__tests__/errorLogging.test.ts` fails when a console line passes a caught error whole, except the few it names that are not API errors
- [`src/types/index.ts`](src/types/index.ts) — TypeScript types mirroring the backend. Two are checked against it: the sheet types in `src/types/game-systems/` against the backend's Zod schemas, and `GameSystem` (`src/types/gameSystem.ts`) against `schema.prisma`. `backend/src/__tests__/keepInStep.test.ts` fails when either drifts, and names the frontend line
- [`src/index.css`](src/index.css) — the theme tokens and the shared utilities. `touch-target` makes a control at least 44 by 44 CSS px where the primary pointer is coarse (a phone or a tablet) and leaves its size alone for a mouse: give it to any control a finger must hit that is not a `<Button iconOnly>` or `<Button size="sm">`, which carry it already. It sets no display, so a lone icon is centred by the control's own classes (`inline-flex items-center justify-center`); a menu item takes `pointer-coarse:min-h-11` instead, and a menu `pointer-coarse:max-h-[calc(100dvh-1rem)]` with `pointer-coarse:overflow-y-auto`. jsdom evaluates no media query, so a test asserts the class. Where the pointer is coarse, every text box, dropdown and text area is drawn at 16 px or more, since Safari on iOS zooms the page when a smaller one takes focus: `text-xs` and `text-sm` read 16 px on a control there, a control with no size class takes its parent's size but not less, and the sizes in pixels below 16 that components write are named in a rule of their own, which `styles/__tests__/touchFormControls.test.ts` keeps complete; it also refuses a text size it cannot read (em, a percentage, `clamp()`, a variable), a font size in a style object and a font size in a stylesheet it does not know
- [`src/themes.ts`](src/themes.ts) — built-in color themes and font families
- [`src/assets/fonts/`](src/assets/fonts/) — the typefaces those font families name, served by the instance itself, with one `@font-face` per family and character range (and per weight, for a family with no variable font) in `fonts.css` and the licences in `OFL.txt`. A new font family needs its files and rules here; `src/__tests__/fonts.test.ts` fails until each family a font choice names first has them
- [`src/components/character-sheets/`](src/components/character-sheets/) — per-game-system character sheet implementations
- [`src/components/campaign/map/mapPointer.ts`](src/components/campaign/map/mapPointer.ts) — `MapPointer`, the one shape a map tool reads a pointer in, made from a pointer event (or the context menu's mouse event), with the click count MapCanvas keeps, since a pointer event's own `detail` is 0
- [`src/components/campaign/map/gestures.ts`](src/components/campaign/map/gestures.ts) — the touch gesture recogniser: taps, long-presses, drags and pinches from pointer samples, with no DOM, so each rule is tested alone with fake timers. Mouse and pen samples make no gesture. `longPressAt` lets the map refuse a long-press as a press lands (under a DM tool), and `hold(id)` holds a press when the browser made its own long-press (Android's `contextmenu`), which `isHeld(id)` then reports
- [`src/components/campaign/map/tokenHold.ts`](src/components/campaign/map/tokenHold.ts) — a held token, with no DOM: `heldDrawnAt`, where it is drawn (under the pointer carrying it, else on its own square, so a token a finger tapped up stays on screen after the lift), `carriedSquare`, the square a pointer carries it to with its whole footprint on the map, and the move that puts it back
- [`src/components/campaign/map/toolbarLayout.ts`](src/components/campaign/map/toolbarLayout.ts) — the band across the top of the map (the toolbar, which wraps between its groups of buttons, and the spirit realm label), measured with a ResizeObserver, and where the panels under it start: the AoE panel and the Put back bar keep their stylesheet places under one row of a mouse's buttons and go under the band on a coarse pointer or a wrapped band (`underBand`); while Put back shows, the AoE panel starts under it (`useMeasuredBottom`); the DM tool stack's corner goes under the band when it wraps or the buttons reach the corner (`stackCornerTop`)
- [`src/components/campaign/TokenDetailsCard.tsx`](src/components/campaign/TokenDetailsCard.tsx) — a token's details in the card at the map's bottom-left: its picture, name and square, the hit points the viewer may see (MapCanvas passes what `visibleTokenHp` decides), its conditions in full, its initiative while it is in the turn order, and whether the viewer may move it
- [`src/components/campaign/HeldTokenBar.tsx`](src/components/campaign/HeldTokenBar.tsx) — the bar over the map that names a token a finger or a pen holds and offers **Put back**, the Esc path; a mouse's hold goes back as the pointer leaves the map, so it never shows for one
- [`src/components/campaign/map/selection.ts`](src/components/campaign/map/selection.ts) — the selected token as the keyboard works it, with no DOM: the tokens a viewer steps through with `,` and `.` and their order (the turn order during a fight, then by row from the top and by column), the square an arrow key moves a token to with its whole footprint kept on the map, the pan that keeps the selection in sight, and `settleArrowEcho`, which keeps the server's late echo of an earlier arrow move from drawing the token back. The selection itself is `selectedTokenId` in the game store
- [`src/components/campaign/map/keyboard.ts`](src/components/campaign/map/keyboard.ts) — the map's token keys: `keyBelongsToMap` (only while the map's focus stop or its token menu has the keyboard, and then not while typing, once something else has used the key, on a control that takes keys itself, or with a dialog open; the older map keys, Tab, Escape and the wall keys, keep `isTypingInto` alone), `mapKeyAction` (each key by what it types, never where it sits, with the modifiers each allows), the pacing of a held arrow, and `MAP_SHORTCUTS`, every key the map takes, which the ? window (`components/campaign/ShortcutsPanel.tsx`, held by the campaign page) lists by role. The guides' Keyboard Shortcuts tables spell the same keys as code spans, and `backend/src/__tests__/documentedFacts.test.ts` reads the list as text, one shortcut per line, counts every row, and fails when a table disagrees on the keys or who they are for, or when the screen-reader hint, `MAP_KEYS_HINT`, leaves a token key out
- [`src/components/campaign/map/layerCanvas.ts`](src/components/campaign/map/layerCanvas.ts) — the map canvases at the screen's pixel ratio: the ratio to draw at (`effectiveDpr`, at most 3 and within `MAX_BACKING_PIXELS` per canvas), the pixel store and CSS size (`sizeBackingStore`, which assigns nothing that has not changed, since assigning a size clears the canvas), the one world transform (`applyViewport`), `clearLayer`, and the size the map-sized lighting canvases are given within the same limit (`withinBackingLimit`). Coordinates everywhere else stay in CSS pixels, and each layer sets its world transform with `applyViewport` only
- [`src/components/common/Markdown.tsx`](src/components/common/Markdown.tsx) — the one Markdown renderer (notes, documents). Import it; do not use `react-markdown` directly, so raw HTML stays off and the plugin set stays the same everywhere
- [`src/test/`](src/test/) — the Vitest setup file, which adds the jest-dom matchers to `expect` through `@testing-library/jest-dom/vitest` and stubs the pointer capture jsdom lacks; `pointer.ts`, which fires pointer events as a browser does (no `detail`, a move's `button` -1, a second button as a move); `waitForDialogFocus`, which a test calls before typing into a dialog that has just opened: the dialog moves focus to its first control on the next animation frame, and keys typed after that move are lost. It waits for a frame of its own, since a field with `autoFocus` puts focus inside the dialog before that move; and `recordingCanvas.ts`, for a test that looks at what the map's layers draw through MapCanvas: every canvas gets a context that records its calls, and the pictures jsdom never loads wait to be loaded by hand
- [`e2e/`](e2e/) — a handful of Playwright smoke tests: a real browser against a running instance, in Chromium at desktop and phone sizes and in WebKit on an iPhone and an iPad. CI runs them against the production stack; `e2e/instance.ts` says which settings they read, and `docs/DEVELOPMENT.md` how to run them locally. Vitest leaves the folder alone. Keep them few: behaviour belongs in Vitest tests
- [`vite.config.ts`](vite.config.ts) — the production build (Vite 8) removes every `console.log`, `console.info`, `console.debug` and `console.trace` call (`build.rolldownOptions.treeshake.manualPureFunctions`), and the minifier drops `debugger`; `console.error` and `console.warn` stay. The dev server keeps every log, and CI fails if one of four known `console.log` lines turns up in the bundle. It also names the five `vendor-*` chunks, and builds for Chrome and Edge 111, Firefox 114 and Safari 16.4, Vite's default
- [`security-headers.conf`](security-headers.conf) — the Content-Security-Policy and other headers the production image serves the app page with. Included by [`nginx.conf`](nginx.conf) in every location, because nginx does not inherit them. Anything loading from a new host has to be allowed here, and the dev server has no policy, so a violation only shows up in a production build
